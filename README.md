# wireproxy-control

Прокси-стек с маршрутизацией по доменам для Windows и macOS. Два VPN-канала на
выбор — **WireGuard** (wireproxy, userspace, без прав администратора) и **VLESS**
(Xray-core: Reality, TLS, ws, grpc) — и веб-панель управления. Весь трафик
браузера проходит через встроенный менеджер, который по каждому домену решает:
отправить в VPN или открыть напрямую.

```
браузер ──> менеджер :8081 ──┬─> wireproxy (:25345) ── WireGuard-туннель ──> интернет
                             ├─> xray       (:25346) ── VLESS-туннель      ──> интернет
                             └─> напрямую
```

## Требования

- Node.js 18+ (https://nodejs.org)
- Windows 10/11 или macOS (Intel / Apple Silicon)
- Конфиг WireGuard и/или ссылка `vless://` от вашего провайдера/сервера

## Установка

### Windows

1. Получите папку проекта (git clone или скачанный архив).
2. В папке проекта выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File install.ps1 -Autostart
   ```

   Скрипт скачает `wireproxy.exe` и `xray.exe`, создаст конфиги из примеров и
   добавит скрытый автозапуск (`-Autostart` можно опустить).

3. Положите свой WireGuard-конфиг в `wg.conf` (см. «Настройка WireGuard»).
   Если WireGuard не нужен — пропустите этот шаг, стек будет работать
   только через VLESS (см. «Настройка VLESS»).

4. Запустите стек: `start-hidden.vbs` — скрыто, без окон; `start.bat` — с
   видимым окном лога (для отладки). Остановка — `stop.bat`.

5. Откройте панель http://127.0.0.1:8080/ и выполните первичную настройку.

### macOS

```bash
git clone https://github.com/devcustrom/vless-pac-proxy.git ~/wireproxy
cd ~/wireproxy
# (опционально) положите сюда свой wg.conf
./mac-install.sh
```

Скрипт скачает бинарники под вашу архитектуру и установит LaunchAgent:
автозапуск при входе и автоматический перезапуск при падении. Если установлены
Xcode Command Line Tools, он же соберёт иконку в строке меню (Swift) — аналог
трея Windows. Подробности — в [README-MAC.md](README-MAC.md).

> **Важно:** каждому устройству — свой клиентский конфиг/ключ на сервере.
> Два устройства с одним ключом одновременно работать не будут: сервер видит
> один peer, и сессии перебивают друг друга.

## Настройка WireGuard

`wg.conf` — обычный конфиг WireGuard-клиента. Минимальный вид:

```ini
[Interface]
PrivateKey = <ваш приватный ключ>
Address = 10.66.66.2/32
DNS = 1.1.1.1,1.0.0.1

[Peer]
PublicKey = <публичный ключ сервера>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Особенности:

- `Address` указывайте с префиксом `/32` (`/128` для IPv6) — так требует wireproxy.
- Конфиг может быть взятым у панели вашего сервера (AmneziaWG не поддерживается).
- Если на сервере нет рабочего IPv6 — не добавляйте адреса `::/0` и IPv6 в
  `Address`: двойные (dual-stack) сайты будут висеть на мёртвом v6.
- **Обязательно проверьте `MTU`**: при дефолтных 1420 у многих провайдеров
  теряется полноразмерный сегмент, и каждый новый запрос через туннель
  выполняется ~5 секунд из-за TCP-ретрансмиссий, а некоторые приложения рвут
  соединения по таймауту (`ECONNRESET`, «socket closed unexpectedly»).
  `MTU = 1280` снимает проблему (цена — ~2% скорости). Если туннель тормозит,
  первым делом уменьшайте MTU: 1280, затем 1200.
- Файл содержит приватный ключ — не публикуйте и не коммитьте его
  (`.gitignore` уже это учитывает).

## Настройка VLESS

1. Откройте панель → карточка **«VLESS (Xray)»**.
2. Вставьте ссылку вида
   `vless://uuid@host:port?security=reality&sni=...&pbk=...&sid=...&flow=xtls-rprx-vision#name`
   → «Сохранить». Поддерживаются Reality, TLS, ws и grpc; прежний конфиг
   сохраняется как `xray-config.json.bak`.
3. Выберите, куда направлять VPN-домены: **WireGuard** или **VLESS**
   (радиокнопки под полем ссылки).
4. Домены, которым нужен именно VLESS, добавьте в список
   **«Домены только через VLESS»** (файл `vless-domains.txt`).

Если канал не настроен (нет `wg.conf` или `vless://` ссылки), он просто
отключается: в статусе — «не настроен», домены автоматически идут через
доступный канал. Если не настроен ни один — маршрутизация не работает и
панель прямо об этом предупреждает.

### Пул конфигов из подписок (free VLESS/Reality)

Вместо одной ссылки можно подключить подписки: панель → карточка
«Пул конфигов (подписки)». Источники хранятся в `subscriptions.txt`
(по умолчанию — публичные подписки
[igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia):
BLACK_VLESS и Reality White-Lists, обновляются ежедневно).

- **«Проверить конфиги»** — качает подписки, разбирает `vless://` и `ss://`
  (остальные протоколы пропускаются), прогоняет каждый конфиг через
  `xray -test` и пробует реальный туннель до `api.ipify.org`; показывает
  рабочие конфиги с задержкой (~30–60 с на сотню конфигов).
- **«Использовать»** — применяет конфиг к VLESS-каналу одной кнопкой.
- **Авто-ротация**: если VLESS-канал перестал проходить трафик, а в пуле есть
  рабочий конфиг, менеджер сам переключается на него (не чаще раза в 5 минут).
- Free-конфиги живут недолго: часть всегда мертва, поэтому проверка — норма:
  из сотни может остаться 2–5 рабочих, зато подписки обновляются каждый день.

Безопасность: сервер качает только `http/https`, резолвит хост и отсекает
localhost, приватные и зарезервированные адреса — в том числе на каждом
редиректе. Редиректы проверяются вручную, размер ответа ограничен.

### Автоматизация

- **Автообновление подписок**: при старте (через ~40 с) и далее по расписанию —
  по умолчанию каждые 6 часов. Настраивается в панели (1/3/6/12/24 часа или
  выключить). После обновления пул сразу используется для восстановления.
- **Автовосстановление**: раз в минуту каналы проверяются реальной пробой.
  Если VLESS не проходит трафик (или упали оба канала) — запускается
  восстановление: при устаревшем пуле подписки обновляются, затем применяется
  первый рабочий конфиг из пула. Если он сразу не поднялся — на следующей
  пробе берётся следующий кандидат; не чаще одного переключения в минуту,
  список испробованных сбрасывается через 15 минут.
- **WireGuard упал, VLESS жив** — VPN-домены автоматически идут через VLESS
  (в лог пишется уведомление); когда WG восстанавливается, маршрутизация
  возвращается к основному каналу.
- Всё это включается/выключается в карточке пула (галочки «Автообновление
  подписок» и «Автопереключение на рабочий конфиг»), состояние хранится в
  `settings.json`.

## Включение системного прокси

Самый простой путь — галка **«Системный прокси»** в панели. Она выставляет
HTTP-прокси `127.0.0.1:8081` для текущего пользователя (Windows: параметры
WinINET; macOS: `networksetup` для активного сетевого сервиса) с исключениями
для `localhost`, локальных подсетей и релея ZCode (`*.z.ai`).

Ручные варианты (если галка недоступна):

- **Windows:** Win+R → `inetcpl.cpl` → Подключения → Настройка сети →
  «Использовать прокси-сервер», адрес `127.0.0.1`, порт `8081`.
- **macOS:** Системные настройки → Сеть → активный сервис → Подробнее →
  Прокси → «Веб-прокси (HTTP)» и «Защищённый веб-прокси (HTTPS)»:
  сервер `127.0.0.1`, порт `8081`.
- **Firefox** может использовать отдельные настройки: Параметры сети →
  «Использовать системные настройки прокси» (по умолчанию) либо вручную
  HTTP-прокси `127.0.0.1:8081`.

После включения перезапустите браузер, чтобы он подхватил настройки.
Chromium-браузеры (Chrome, Edge, Яндекс) следуют системным настройкам.

Отдельно существует PAC-файл `http://127.0.0.1:8080/proxy.pac` — он крошечный
и просто направляет весь трафик в менеджер; нужен для нестандартных сценариев.

### Приложения со своим HTTP-клиентом (opencode и т.п.)

Браузеры следуют системным настройкам, но многие приложения (opencode desktop,
CLI-утилиты на Node/Bun/Rust) читают только переменные окружения. Задавать их
глобально не нужно и рискованно: **работающие процессы сохраняют окружение,
полученное при старте** — если остановить стек, уже запущенные приложения
(включая dev-серверы и IDE-терминалы) будут стучаться в мёртвый прокси и
получать `ECONNREFUSED 127.0.0.1:8081`.

В репозитории есть точечный лончер `start-opencode.vbs`: он выставляет
`HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`/`NODE_USE_ENV_PROXY` только для
запускаемого OpenCode. Положите ярлык на него на рабочий стол и запускайте
opencode им (сам стек при этом должен быть запущен).

Если глобальные переменные всё же нужны другим утилитам — задайте их вручную:

```powershell
[Environment]::SetEnvironmentVariable('HTTPS_PROXY','http://127.0.0.1:8081','User')
[Environment]::SetEnvironmentVariable('HTTP_PROXY','http://127.0.0.1:8081','User')
[Environment]::SetEnvironmentVariable('NO_PROXY','localhost,127.0.0.1,::1,.local,.z.ai','User')
[Environment]::SetEnvironmentVariable('NODE_USE_ENV_PROXY','1','User')
```

и помните: после остановки стека их надо удалить, а приложения и IDE —
перезапустить (окружение меняется только у новых процессов):

```powershell
[Environment]::SetEnvironmentVariable('HTTPS_PROXY','','User')
```

`stop.bat` сам вычищает глобальные переменные и системный прокси; `start-hidden.vbs`
их больше не выставляет.

## Маршрутизация

| Что | Куда идёт |
|---|---|
| Локальные адреса, `*.local`, IP-литералы | напрямую |
| Российские сайты-исключения (itdog outside) | напрямую (даже если попали в списки) |
| Списки недоступных из РФ (itdog inside + реестр РКН, ~74 тыс. доменов) | основной VPN-канал |
| Ваши домены из `extra-domains.txt` | основной VPN-канал |
| Ваши домены из `vless-domains.txt` | только VLESS |
| Всё остальное | напрямую |

Поддомены учитываются автоматически: запись `example.com` покрывает
`a.example.com` любой вложенности. Списки обновляются при старте и раз в
12 часов; если источник недоступен напрямую, он скачивается через собственный
VPN. Сбой источников не ломает маршрутизацию — остаётся последний удачный
список.

## Панель управления

| Раздел | Назначение |
|---|---|
| Статус | Состояние обоих каналов, их выходные IP, счётчики доменов |
| VLESS (Xray) | Вставка `vless://` ссылки, выбор основного канала, домены только для VLESS |
| Недавние сайты (мимо VPN) | Домены, которые браузер открывал напрямую; кнопка «через VPN» |
| Проверка сайта | Сравнивает ответ напрямую и через VPN, выдаёт вердикт, позволяет добавить |
| Свои домены | `extra-domains.txt` — всегда через VPN |
| Системный прокси | Включение/выключение прокси для всей системы |
| Локальные домены (плагин) | Домен → локальный порт: реверс-прокси и свой домен у панели |

Адреса и порты: панель `127.0.0.1:8080`, прокси `127.0.0.1:8081`, SOCKS5
wireproxy `:25344`, HTTP wireproxy `:25345`, HTTP xray `:25346`.
Все слушают только loopback-интерфейс.

## Плагин локальных доменов

Дополнительный модуль `local-domains.js`: реверс-прокси по заголовку Host,
который открывает локальные сервисы по красивым доменам.

- Правила в `local-domains.txt`: `домен = порт` (редактируется вручную и в
  панели, карточка «Локальные домены (плагин)»).
- Реверс-прокси слушает `127.0.0.1:80` (порт меняется полем `localProxyPort`
  в `settings.json`), работает только на loopback и проксирует только на
  `127.0.0.1:<порт из конфига>`; поддерживаются HTTP и WebSocket/upgrade.
- **Свой домен у панели**: по умолчанию `panel.localhost = 8080` — панель
  открывается как `http://panel.localhost/` (allowlist Host в панели
  подхватывает домены, указывающие на её порт, автоматически).
- `*.localhost` браузеры (Chrome/Edge/Firefox) резолвят в loopback без правки
  hosts. Для «настоящих» имён (например `app.test`) запустите
  `local-domains-hosts.bat` от имени администратора — он синхронизирует блок
  записей в hosts между маркерами и сбрасывает DNS-кэш.
- HTTPS для локальных доменов не поднимается (нужен собственный CA и
  сертификаты) — используйте `http://`.
- Неизвестный домен получает 404 со списком настроенных.

## Повседневное использование

| Действие | Windows | macOS |
|---|---|---|
| Запуск (скрыто) | `start-hidden.vbs` | `./mac-start.sh` (или автозапуск) |
| Запуск с логом | `start.bat` | — |
| Остановка | `stop.bat` | `./mac-stop.sh` |
| Логи | `manager.log` | `manager.log` |

Автозапуск: Windows — ярлык в «Автозагрузке», macOS — LaunchAgent. Оба
запускают стек без окон и перезапускают его при падении.

Иконка управления: Windows — в системном трее (`tray.ps1`), macOS — в строке
меню (Swift-приложение `WireproxyTray`, собирается установщиком при наличии
Xcode Command Line Tools). Меню: открыть панель, обновить списки,
перезапустить VPN-прокси, остановить стек и выйти.

## Частые проблемы

- **«Ни один VPN-канал не настроен»** — положите `wg.conf` и/или вставьте
  `vless://` ссылку в панели.
- **Сайт не открывается, хотя включён в список** — проверьте статус канала
  в панели; если канал «не работает», посмотрите `manager.log`. Настройки
  маршрутизации применяются сразу, перезапуск не нужен.
- **`ERR_PROXY_CONNECTION_FAILED` в браузере** — системный прокси включён, а
  менеджер не работает (например, остановлен вручную или упал). `stop.bat` /
  `./mac-stop.sh` выключают прокси автоматически, так что правильный путь:
  остановить стек ими, затем запустить снова и включить прокси галкой в
  панели. Если менеджер был убит жёстко — снимите галку «Системный прокси»
  после старта (или один раз `stop.bat`, он поправит настройку в реестре).
- **Проверка сайта показывает 403 на обоих путях** — обычно это анти-бот
  проверка Cloudflare: curl её не проходит, а браузер проходит. Ориентируйтесь
  на браузер.
- **Браузер не использует прокси** — перезапустите браузер; отключите
  расширения-прокси (SwitchyOmega и подобные), они перебивают системные
  настройки.
- **macOS:** при переключении Wi-Fi ↔ Ethernet включите галку системного
  прокси заново (настройки хранятся отдельно для каждого сервиса).
- **Порт занят** — остановите старый экземпляр (`stop.bat` / `./mac-stop.sh`)
  или освободите порт 8080/8081.
- **Два устройства с одним ключом WireGuard** — разнесите по разным
  клиентам на сервере.

## Безопасность

- `wg.conf` и `xray-config.json` содержат приватные ключи. Не публикуйте их;
  `.gitignore` исключает их из git, включая резервные копии.
- Все компоненты слушают только `127.0.0.1` — из сети доступ к панели и
  прокси невозможен.
- Панель защищена от CSRF и DNS-rebinding: принимает запросы только с
  `Host: 127.0.0.1:8080` / `localhost:8080`, а изменяющие запросы — только с
  заголовком `X-WPC: 1` (сторонний сайт не сможет его отправить без
  CORS-preflight, которого сервер не разрешает). Скрипты остановки и трей
  отправляют этот заголовок.
- Прокси и загрузка подписок не ходят в локальные/приватные/резервные адреса:
  проверяются и литеральные IP, и **фактический IP в момент подключения**
  (анти-SSRF и анти-DNS-rebinding); каждое перенаправление подписки
  проверяется отдельно, размер ответа ограничен.
- Файлы состояния создаются только по фиксированным именам внутри каталога
  проекта (проверка basename + границы каталога).
- Панель меняет системные настройки прокси только по явному действию
  пользователя (галка/кнопка).

Статический аудит Mimosa (deep, seal `c464c667…`): **0 находок**. При этом
статус скана — `inconclusive` (частичный граф вызовов: динамическая
диспетчеризация вне анализа), поэтому это не полноценный пентест: отсутствие
находок не гарантирует отсутствие уязвимостей.

## Структура репозитория

```
manager.js        демон: умный прокси :8081, панель :8080, управление wireproxy/xray,
                  маршрутизация по доменам, журнал посещений, системный прокси
update-domains.js загрузка списков доменов (itdog inside/outside, Re-filter-lists),
                  генерация PAC
vless-to-xray.js  парсер vless:// ссылок -> конфиг Xray
local-domains.js  плагин локальных доменов: реверс-прокси по Host (HTTP/WS)
ui.html           веб-панель (без внешних зависимостей)
tray.ps1          иконка в трее Windows
tray.swift        иконка в строке меню macOS (swiftc -O tray.swift -o WireproxyTray)
start-hidden.vbs  скрытый запуск стека (используется ярлыком автозапуска)
start.bat         запуск с окнами (отладка)
stop.bat          остановка всего
install.ps1       установщик для Windows (бинарники, конфиги, автозапуск)
mac-install.sh    установщик для macOS; mac-start.sh / mac-stop.sh
com.wireproxy.manager.plist.template  шаблон LaunchAgent менеджера
com.wireproxy.tray.plist.template     шаблон LaunchAgent иконки в меню-баре
```

Приватные и генерируемые файлы (в git не попадают): `wg.conf`,
