# wireproxy-control

Один бинарник для Windows и macOS: прокси-стек с маршрутизацией **по доменам**.
Два VPN-канала на выбор — **WireGuard** (wireproxy, userspace, без прав
администратора) и **VLESS/SS** (Xray-core: Reality, TLS, ws, grpc) — плюс
веб-панель и иконка в трее.

```
браузер ──> менеджер :8081 ──┬─> wireproxy (:25345) ── WireGuard-туннель ──> интернет
                             ├─> xray       (:25346) ── VLESS-туннель      ──> интернет
                             └─> напрямую
```

По каждому домену менеджер решает сам: отправить в VPN (списки заблокированных
и ваши домены) или открыть напрямую. Списки обновляются автоматически, а если
VLESS-канал умирает — подписки перепроверяются и конфиг меняется сам.

## Возможности

- **Умная маршрутизация**: списки itdog (внутри/снаружи РФ) + Re-filter RKN,
  свои домены, отдельный список «только через VLESS», PAC-файл.
- **Два канала и автопереключение**: WireGuard и VLESS/SS; при падении одного
  канала VPN-домены уходят в живой.
- **Пул конфигов из подписок**: `vless://` и `ss://`, проверка каждого конфига
  через `xray -test` и реальные пробы, автоподмена мёртвого сервера.
- **Локальные домены**: `http://` и `https://` реверс-прокси на loopback,
  собственный CA (переиспользуется старый), WebSocket/HMR, скрипты доверия
  и синхронизации hosts.
- **Панель и трей**: статус каналов, включение системного прокси, проверка
  сайта «напрямую / через VPN», недавние сайты, настройки.
- **Установка без Node.js**: движки wireproxy и Xray скачиваются при первом
  запуске с проверкой sha256 по закреплённым версиям.
- **Автозапуск**: HKCU `Run` на Windows, LaunchAgent на macOS.
- **MCP-сервер** для агентов: локальные домены и порты как инструменты.

## Установка (Windows 10/11, x64)

1. Скачайте `wireproxy-control-windows-x64.zip` со страницы Releases и
   распакуйте в любую папку (например, `C:\Tools\wireproxy-control`).
2. Запустите `wireproxy-control.exe`.
3. При первом запуске бинарник:
   - скачает `wireproxy.exe` и `xray.exe` (с проверкой контрольных сумм);
   - создаст папку данных и сертификаты;
   - откроет панель в браузере.
4. В панели в блоке **«Быстрый старт»** добавьте канал: положите `wg.conf`
   рядом с программой или вставьте `vless://`-ссылку, затем включите
   системный прокси.

Консольное окно при обычном запуске не нужно: приложение живёт в трее
(иконка рядом с часами). Меню трея: открыть панель, установить сертификаты,
обновить списки, перезапустить движки, выход.

> **SmartScreen.** Бинарник не подписан сертификатом разработчика, поэтому
> Windows может показать «Windows защитила ваш компьютер». Нажмите
> «Подробнее» → «Всё равно выполнить». Это ожидаемо для сборок без подписи.

### Автозапуск (Windows)

```powershell
wireproxy-control.exe install
```

Команда прописывает `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
со скрытым запуском (`--hidden`) и, если движков ещё нет, скачивает их.
Удалить автозапуск: `wireproxy-control.exe uninstall` (данные и сертификаты
остаются).

## Установка (macOS, universal: Intel и Apple Silicon)

1. Скачайте `wireproxy-control-macos-universal.zip` и распакуйте.
2. Запустите `wireproxy-control` из терминала или Finder.
   Gatekeeper: ПКМ → «Открыть» → «Открыть» (бинарник не подписан).
3. Автозапуск: `./wireproxy-control install` — создаёт
   `~/Library/LaunchAgents/com.wireproxy-control.plist`.

macOS-часть (трей, системный прокси через `networksetup`, LaunchAgent)
собирается в CI, но требует ручной проверки на живом Mac — считайте её
beta. Если что-то не работает, запустите бинарник с `--no-tray` и смотрите
`manager.log`.

## Где лежат данные

- **Portable**: если рядом с бинарником есть `wg.conf`, `settings.json` или
  `wireproxy.conf`, данные читаются и пишутся прямо в этой папке.
- **Обычный режим**: `%LOCALAPPDATA%\wireproxy-control` (Windows) или
  `~/Library/Application Support/wireproxy-control` (macOS).
- Переопределить: `--data-dir <путь>` или переменная `WPC_DATA_DIR`.

| Файл | Назначение |
| --- | --- |
| `settings.json` | `vpnDefault`, `autoRotate`, `autoPoolRefreshHours`, `localProxyPort`, `localHttpsPort` |
| `wg.conf` | конфиг WireGuard-клиента (ключи, Endpoint, AllowedIPs) |
| `wireproxy.conf` | сгенерированный конфиг wireproxy (порты 25344/25345) |
| `xray-config.json` | активный VLESS/SS-конфиг (есть `.bak`) |
| `extra-domains.txt` | ваши домены через VPN |
| `vless-domains.txt` | домены, которые всегда через VLESS |
| `local-domains.txt` | локальные домены: `домен = порт` |
| `subscriptions.txt` | URL подписок |
| `pool-state.json` | проверенный пул конфигов и активная ссылка |
| `certs/` | локальный CA и сертификаты доменов |
| `manager.log` | журнал менеджера и движков |
| `instance.lock` | защита от второго запуска |

## Настройка WireGuard

`wg.conf` — обычный клиентский конфиг WireGuard:

```ini
[Interface]
PrivateKey = <ваш приватный ключ>
Address = 10.66.66.2/32
DNS = 1.1.1.1,1.0.0.1

[Peer]
PublicKey = <публичный ключ сервера>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Важно:

- `Address` — с префиксом `/32` (`/128` для IPv6), так требует wireproxy.
- **MTU**: если туннель «тормозит» на каждом новом соединении, поставьте
  `MTU = 1280` в `[Interface]`. Дефолтные 1420 у многих провайдеров приводят
  к потере крупных пакетов и TCP-ретрансмиссиям.
- AmneziaWG **не** поддерживается — это отдельный протокол.
- Каждому устройству — свой ключ/конфиг: сервер видит один peer, и две
  сессии с одним ключом перебивают друг друга.

Если WireGuard не нужен, оставьте только VLESS: панель сама направит
VPN-домены в живой канал.

## Настройка VLESS/SS

В панели в блоке «VLESS (Xray) — второй канал» вставьте ссылку
`vless://…` (Reality, TLS, ws, grpc) или `ss://…` и нажмите «Сохранить».
Конфиг сохраняется в `xray-config.json`, xray перезапускается.

Подписки: в блоке «Пул конфигов» добавьте URL подписки (обычный текст или
base64). Менеджер:

1. загружает ссылки (только http/https, с проверкой адресов и лимитом 5 МиБ);
2. гоняет каждую через `xray -test`;
3. поднимает тестовый xray с несколькими inbound и реально проверяет
   выходной IP;
4. сортирует рабочие по задержке и сохраняет в `pool-state.json`;
5. при падении активного VLESS-канала переключается на рабочий сам
   (не чаще раза в минуту, цикл — 15 минут).

## Локальные домены и HTTPS

Блок «Локальные домены (плагин)»: домен → локальный порт. Менеджер слушает
`http://127.0.0.1:80` и `https://127.0.0.1:443` (порты меняются в
`settings.json`) и проксирует запросы по заголовку `Host`/SNI на
`localhost:<порт>`. Поддерживаются WebSocket (Vite HMR и т.п.).

- `*.localhost` браузеры резолвят в `127.0.0.1` сами — правка hosts не нужна.
- Для «настоящих» имён запустите `wireproxy-control.exe sync-hosts` и затем
  созданный `local-domains-hosts.bat` от администратора (macOS — `.command`).
- HTTPS: кнопка «Установить сертификаты» (или `trust-certs`) запускает
  `local-domains-trust.bat` с UAC и добавляет CA в доверенные. Firefox:
  `about:config` → `security.enterprise_roots.enabled = true`.
- Существующий `certs/ca.key|ca.crt` переиспользуется, поэтому ранее
  установленное доверие не сбрасывается.

## Панель и системный прокси

Панель: <http://127.0.0.1:8080/> (порт меняется `--panel-port`). Если порт
занят, менеджер сам возьмёт следующий свободный — фактический порт виден в
`manager.log` и в трее. Включение «Системный прокси» прописывает
`127.0.0.1:8081` в настройки прокси системы (реестр + WinINET на Windows,
`networksetup` на macOS). При выходе прокси выключается автоматически, чтобы
не оставить браузер без интернета.

Проверка сайта: «Проверить» открывает домен напрямую и через VPN и предлагает
добавить его в список, если VPN помогает.

PAC-файл: <http://127.0.0.1:8080/proxy.pac> — `PROXY 127.0.0.1:8081` для
доменов списков, остальное `DIRECT`.

## Команды

| Команда | Что делает |
| --- | --- |
| `wireproxy-control` | менеджер + панель + трей (основной режим) |
| `wireproxy-control install` | автозапуск (+ скачивание движков) |
| `wireproxy-control uninstall` | убрать автозапуск (данные остаются) |
| `wireproxy-control stop` | остановить менеджер, выключить системный прокси |
| `wireproxy-control trust-certs` | установить локальный CA (UAC/пароль) |
| `wireproxy-control sync-hosts` | подготовить скрипт синхронизации hosts |
| `wireproxy-control mcp` | MCP-сервер (stdio JSON-RPC) |
| `wireproxy-control version` | версия |

Флаги: `--data-dir <путь>`, `--panel-port <порт>`, `--hidden` (без окна),
`--no-tray` (сервисный режим без иконки).

## MCP для агентов

`wireproxy-control mcp` — stdio JSON-RPC сервер (protocol 2024-11-05) с
инструментами:

- `local_domains_list` — список локальных доменов;
- `local_domains_add` — добавить `домен → порт`;
- `local_domains_remove` — убрать домен;
- `local_domains_probe` — проверить, отвечает ли локальный домен;
- `local_ports` — слушающие локальные порты.

Пример конфигурации MCP-клиента:

```json
{
  "mcpServers": {
    "wireproxy": {
      "command": "C:\\Tools\\wireproxy-control\\wireproxy-control.exe",
      "args": ["mcp"]
    }
  }
}
```

| Порт | Что |
| --- | --- |
| 8080 | веб-панель и API (только 127.0.0.1) |
| 8081 | умный прокси (системный/PAC) |

## Сборка из исходников

Нужен Rust (stable) и git:

```bash
cargo build --release
cargo test
```

Бинарник: `target/release/wireproxy-control` (`wireproxy-control.exe` на
Windows). CI (GitHub Actions) собирает Windows x64 и macOS universal и
запускает `cargo fmt --check`, `clippy -D warnings`, тесты.

Движки не входят в бинарник: версии закреплены в `src/engines/downloads.rs`
(wireproxy v1.1.3, Xray v26.11.9) вместе с sha256. Скачивание идёт с GitHub
Releases при первом запуске или через `install`.

## Безопасность и ограничения

- Панель, API, прокси и локальные домены слушают только loopback.
- POST-запросы API требуют заголовок `X-WPC: 1`; Host проверяется по
  allowlist (включая панельные локальные домены).
- При подключении проверяются запрещённые IP-диапазоны (loopback, private,
  link-local, multicast и т.п.) — защита от SSRF/DNS-rebinding.
- Загрузка движков проверяется по sha256; распаковываются только ожидаемые
  файлы, без путей из архива.
- Секреты (`wg.conf`, `xray-config.json`, `pool-state.json`, `settings.json`,
  `certs/`) не попадают в git — см. `.gitignore`.
- Проект не проходил внешний аудит; глубокая проверка Mimosa даёт 0 находок
  при неполном покрытии динамических вызовов. Не считайте его «гарантированно
  безопасным» — используйте на свой риск.

## Старый стек (legacy)

Папка `legacy/` содержит прежнюю реализацию на Node.js/PowerShell/Swift
(`manager.js`, `tray.ps1`, `local-tls.js` и т.д.). Она оставлена для сверки
поведения и не используется бинарником. Форматы файлов совместимы, поэтому
существующая папка данных подхватывается без конвертации.
