# wireproxy-control

Умный прокси-стек для Windows и macOS: весь трафик браузера проходит через
локальный менеджер, который **по каждому домену** решает — отправить его в VPN
или открыть напрямую. VPN-каналов два на выбор: **WireGuard** (wireproxy,
userspace, без прав администратора) и **VLESS** (Xray-core, поддерживает
Reality/TLS/ws/grpc).

```
браузер ──> менеджер :8081 ──┬─> wireproxy (:25345) ── WireGuard-туннель ──> интернет
                             ├─> xray       (:25346) ── VLESS-туннель      ──> интернет
                             └─> напрямую (мимо VPN)
```

Никаких PAC-скриптов с тысячами доменов: решение принимается в памяти
менеджера, поэтому нет лимита Chromium в 1 МБ на PAC и обновление списков
действует мгновенно.

## Возможности

- **Сплит-роутинг по доменам**: списки заблокированных в РФ (itdog.info +
  полный реестр РКН с автопроверкой, ~74 тыс. доменов) идут через VPN,
  остальное — напрямую. Российские сайты-исключения (itdog outside) — всегда
  напрямую.
- **Два VPN-канала**: WireGuard и VLESS; выбор основного канала в один клик +
  отдельный список доменов «только через VLESS».
- **Веб-панель** (http://127.0.0.1:8080/): статусы обоих каналов и их выходные
  IP, «Недавние сайты (мимо VPN)» — все домены, которые браузер открыл
  напрямую, добавляются в VPN одной кнопкой; «Проверка сайта» (сравнение
  ответа напрямую и через VPN); включение/выключение системного прокси.
- **Иконка в трее** (Windows): панель, обновление списков, перезапуск, выход.
- **Демон-менеджер**: сам запускает и перезапускает wireproxy/xray, обновляет
  списки при старте и раз в 12 часов (при сбое источника качает через свой же
  VPN), ведёт журнал.
- Автозапуск: Windows — ярлык в «Автозагрузке» (скрыто), macOS — LaunchAgent.

## Быстрый старт — Windows

Требуется Node.js.

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -Autostart
```

Скрипт скачает `wireproxy.exe` и `xray.exe`, создаст конфиги из примеров и
пропишет скрытый автозапуск. Дальше:

1. Вставьте реальный WireGuard-конфиг в `wg.conf`
   (адрес с `/32`; если на сервере нет рабочего IPv6 — оставьте только v4).
2. Запустите `start-hidden.vbs` (скрыто) или `start.bat` (с окнами, отладка).
3. Панель: http://127.0.0.1:8080/ → галка «Системный прокси».
4. Для VLESS: вставьте вашу `vless://` ссылку в карточке «VLESS (Xray)».

## Быстрый старт — macOS

```bash
# скопируйте папку репозитория на мак, положите свой wg.conf и затем:
./mac-install.sh
```

Скрипт скачает бинарники под архитектуру (Apple Silicon/Intel), пропишет
LaunchAgent (автозапуск + перезапуск при падении). Системный прокси включается
галкой в панели (применяется к активному Wi-Fi/Ethernet). Подробности и
отличия — в [README-MAC.md](README-MAC.md).

**Важно:** не запускайте два устройства с одним WireGuard-ключом одновременно —
сессии перебивают друг друга. Каждой машине — свой peer на сервере.

## Только VLESS (без WireGuard)

WireGuard заводить не обязательно. Если `wg.conf` отсутствует (или в нём
заглушки из примера), менеджер не запускает wireproxy, и все VPN-домены
автоматически идут через VLESS — достаточно вставить `vless://` ссылку в
панели. И наоборот: если ссылки VLESS нет, все домены идут через WireGuard.
Индикаторы в панели показывают «не настроен» для отключённого канала, и
ничего не перезапускается вхолостую.

Приоритет: домены из VLESS-списка → VLESS (если настроен), остальные
VPN-домены → основной канал (если он не настроен — доступный).

## Панель управления

| Раздел | Что делает |
|---|---|
| Статус | Состояние обоих каналов, выходные IP, счётчики доменов |
| VLESS (Xray) | Вставка `vless://` ссылки, выбор основного канала, домены «только VLESS» |
| Недавние сайты (мимо VPN) | Домены, открытые браузером напрямую; кнопка «через VPN» |
| Проверка сайта | Сравнение ответа напрямую и через VPN + вердикт + добавление |
| Свои домены | `extra-domains.txt` — всегда через VPN (поддомены учитываются) |
| Системный прокси | Включить/выключить прокси для всей Windows |

Адреса: панель `127.0.0.1:8080`, умный прокси `:8081`, SOCKS5 wireproxy `:25344`,
HTTP wireproxy `:25345`, HTTP xray `:25346`, PAC `http://127.0.0.1:8080/proxy.pac`.

## Повседневные команды

Windows: `start-hidden.vbs` / `start.bat` / `stop.bat`.
macOS: `./mac-start.sh` / `./mac-stop.sh`, логи `tail -f manager.log`.

«Проверка сайта» и вердикты: `403` на обоих путях обычно означает анти-бот
проверку Cloudflare — curl её не проходит, а браузер проходит. Автоматически
собирать коды ответов (403 и т.п.) невозможно без MITM-сертификата — статусы
зашифрованы в TLS; поэтому панель собирает домены, а не статусы.

## Структура репозитория

```
manager.js        демон: умный прокси :8081, панель :8080, lifecycle wireproxy/xray,
                  сплит-роутинг, журнал «мимо VPN», системный прокси (Win registry / mac networksetup)
update-domains.js загрузка списков (itdog inside/outside, Re-filter-lists), крошечный PAC
vless-to-xray.js  парсер vless:// ссылок -> конфиг Xray (Reality/TLS/ws/grpc)
ui.html           веб-панель (vanilla JS, без зависимостей)
tray.ps1          иконка в трее (Windows, WinForms)
start-hidden.vbs  скрытый запуск стека (для ярлыка в Автозагрузке)
start.bat         запуск с окнами (отладка)
stop.bat          остановка всего
install.ps1       установка на Windows (бинарники, конфиги, автозапуск)
mac-install.sh    установка на macOS (+ mac-start.sh / mac-stop.sh)
*.plist.template  шаблон LaunchAgent для macOS
```

Приватные/генерируемые файлы (не в git, см. `.gitignore`): `wg.conf` — ключи
туннеля, `xray-config.json` — UUID из vless-ссылки, `settings.json`,
`proxy.pac`, бинарники, логи.

## Безопасность

- `wg.conf` и `xray-config.json` содержат приватные ключи — никогда не
  публикуйте и не коммитьте их (`.gitignore` защищает по случайности).
- Панель и прокси слушают только `127.0.0.1` — наружу ничего не торчит.
- Панель умеет менять системные настройки прокси — это явное действие
  пользователя в интерфейсе.
