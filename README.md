# wireproxy-control

Один бинарник для Windows и macOS: прокси-стек с маршрутизацией **по доменам**.
Два VPN-канала на выбор — **WireGuard** (wireproxy, userspace, без прав
администратора) и **VLESS/SS** (Xray-core: Reality, TLS, ws, grpc; Outline) — плюс
веб-панель и иконка в трее.

```
браузер ──> менеджер :8081 ──┬─> wireproxy (:25345) ── WireGuard-туннель ──> интернет
                             ├─> xray       (:25346) ── VLESS-туннель      ──> интернет
                             └─> напрямую
```

По каждому домену менеджер решает сам: отправить в VPN (списки заблокированных
и ваши домены) или открыть напрямую. Списки обновляются автоматически, а если
VLESS-канал умирает — подписки перепроверяются и конфиг меняется сам.

## Возможности

- **Умная маршрутизация**: списки itdog (внутри/снаружи РФ) + Re-filter RKN,
  свои домены, списки «только через VLESS» и «только через WireGuard», PAC.
- **Два канала и автопереключение**: WireGuard и Xray (VLESS/VMess/Trojan/SS,
  включая статические ключи Outline);
  при падении одного канала VPN-домены уходят в живой.
- **Несколько WireGuard-конфигов**: хранение, выбор активного, live-тест
  трафика перед применением.
- **Пул конфигов из подписок**: `vless://`, `vmess://`, `trojan://`, `ss://`
  (Outline/Shadowsocks), live-проверка, автоподмена мёртвого сервера. Постоянный HWID устройства
  передаётся в `x-hwid`/`x-device-*` при загрузке подписок.
- **Локальные домены**: `http://` и `https://` реверс-прокси на loopback,
  собственный CA (переиспользуется старый), WebSocket/HMR, скрипты доверия
  и синхронизации hosts.
- **Telegram-прокси**: локальный MTProto для Telegram Desktop; WS-транспорт
  tg-ws-proxy, WireGuard/VLESS и явный direct-режим с автопереключением.
  Sidecar обновляется автоматически по манифесту релиза.
  Подробнее — [TELEGRAM.md](TELEGRAM.md).
- **Обход DPI (Windows)**: раздел с zapret2 (`winws2` + `winws` для
  nfqws-стратегий), служба Windows, WinDivert, автоподбор стратегии и
  провайдера. Можно выбрать несколько пресетов сразу — они объединяются в одну
  службу с профилями под разные сайты и протоколы. Из проверки сайта можно
  сгенерировать стратегии под конкретный ресурс, применить их или сохранить
  в пресеты. Внешний каталог Zaprett загружает готовые стратегии, списки,
  ipsets и fake-payload'ы с проверкой sha256 и указанием автора/источника.
  Бандл скачивается и проверяется по sha256 прямо из панели.
  Подробнее — [ZAPRET.md](ZAPRET.md).
- **История сайтов**: отдельная вкладка «Сайты», фильтры «через VPN / напрямую /
  нужен VPN / без проверки», проверка каждого домена и всего списка, фоновая
  автопроверка новых доменов с авто-добавлением в VPN. У каждого домена есть
  чекбокс VPN: он показывает текущий маршрут и переключает домен между VPN и
  «напрямую» (`direct-domains.txt`).
- **Хранение и бэкапы**: история в SQLite (`wireproxy.db`), резервная копия
  настроек, конфигов, сертификатов и истории одним zip с восстановлением.
- **Панель и трей**: статус каналов, включение системного прокси, проверка
  сайта «напрямую / через VPN / через Zapret», настройки.
- **Бесшовное обновление**: кнопка «Установить» скачивает новый бинарник,
  заменяет его после выхода старого процесса и запускает менеджер снова.
- **Установка без Node.js**: движки wireproxy и Xray скачиваются при первом
  запуске с проверкой sha256 по закреплённым версиям.
- **Автозапуск**: HKCU `Run` на Windows, LaunchAgent на macOS.
- **MCP-сервер** для агентов: локальные домены и порты как инструменты.

## Установка (Windows 10/11, x64)

1. Скачайте готовый бинарник `wireproxy-control-windows-x64.exe` со страницы
   [Releases](../../releases/latest) и положите в любую папку (например,
   `C:\Tools\wireproxy-control`). Для удобства переименуйте его в
   `wireproxy-control.exe` — команды ниже используют это имя.
2. Запустите `wireproxy-control.exe`.
3. При первом запуске бинарник:
   - скачает `wireproxy.exe` и `xray.exe` (с проверкой контрольных сумм);
   - создаст папку данных и сертификаты;
   - предложит включить плагин локальных доменов и задать домен для панели
     (`panel.localhost` по умолчанию);
   - откроет панель в браузере.
4. В панели в блоке **«Быстрый старт»** добавьте канал: вставьте `wg.conf`
   в карточке WireGuard или `vless://`-ссылку, затем включите системный
   прокси.

Плагин доменов — необязательный шаг: его можно включить позже в
**«Настройки» → «Плагины»**. При включении панель предупредит, что для HTTPS
без предупреждений нужно установить локальный CA, и предложит кнопку
«Установить сертификаты».

Документация (этот README и macOS-инструкция) встроена в приложение:
кнопка **«Документация»** в панели. Проверить обновления можно в карточке
**«Обновление»** — она ведёт на прямой бинарник последнего релиза.

Консольное окно при обычном запуске не нужно: приложение живёт в трее
(иконка рядом с часами). Меню трея: текущий статус каналов, переключатели
«Системный прокси» и «Telegram-прокси», «Открыть Telegram», «Открыть панель»,
«Настройки…» и «Выход».

> **SmartScreen.** Бинарник не подписан сертификатом разработчика, поэтому
> Windows может показать «Windows защитила ваш компьютер». Нажмите
> «Подробнее» → «Всё равно выполнить». Это ожидаемо для сборок без подписи.

### Автозапуск (Windows)

```powershell
wireproxy-control.exe install
```

Команда прописывает `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
со скрытым запуском (`--hidden`) и, если движков ещё нет, скачивает их.
Удалить автозапуск: `wireproxy-control.exe uninstall` (данные и сертификаты
остаются).

## Установка (macOS, universal: Intel и Apple Silicon)

1. Скачайте из [Releases](../../releases/latest) `WireproxyControl.app` в
   архиве `.zip` или `.dmg` (есть и отдельный бинарник для Терминала).
2. Распакуйте/перетащите приложение в «Программы» и запустите ПКМ →
   «Открыть» → «Открыть». Если macOS пишет «повреждено»:

   ```bash
   xattr -dr com.apple.quarantine /Applications/WireproxyControl.app
   open /Applications/WireproxyControl.app
   ```

3. Автозапуск: добавьте приложение в «Системные настройки» → «Основные» →
   «Элементы входа» либо выполните
   `/Applications/WireproxyControl.app/Contents/MacOS/wireproxy-control install`.

macOS-часть (трей, системный прокси через `networksetup`, LaunchAgent)
собирается в CI, но требует ручной проверки на живом Mac — считайте её
beta. Если что-то не работает, запустите бинарник с `--no-tray` и смотрите
`manager.log`. Подробности: [README-MAC.md](README-MAC.md).

## Где лежат данные

- **Portable**: если рядом с бинарником есть `wg.conf`, `settings.json` или
  `wireproxy.conf`, данные читаются и пишутся прямо в этой папке.
- **Обычный режим**: `%LOCALAPPDATA%\wireproxy-control` (Windows) или
  `~/Library/Application Support/wireproxy-control` (macOS).
- Переопределить: `--data-dir <путь>` или переменная `WPC_DATA_DIR`.

| Файл | Назначение |
| --- | --- |
| `settings.json` | `vpnDefault`, `autoRotate`, `autoPoolRefreshHours`, `localProxyPort`, `localHttpsPort`, `localDomainsEnabled`, `wireguardEnabled`, `xrayEnabled` |
| `wg.conf` | активный конфиг WireGuard-клиента |
| `wg-configs/` | несколько WireGuard-конфигов (`add/use/remove/test`) |
| `wireproxy.conf` | сгенерированный конфиг wireproxy (порты 25344/25345) |
| `xray-configs/` | сохранённые Xray-конфиги (`add/use/remove/test`) |
| `xray-configs.json` | имена и активный Xray-конфиг |
| `xray-config.json` | активный Xray-конфиг (есть `.bak`) |
| `extra-domains.txt` | ваши домены через VPN (основной канал) |
| `vless-domains.txt` | домены, которые всегда через VLESS |
| `wg-domains.txt` | домены, которые всегда через WireGuard |
| `local-domains.txt` | локальные домены: `домен = порт` |
| `subscriptions.txt` | URL подписок |
| `pool-state.json` | проверенный пул конфигов и активная ссылка |
| `certs/` | локальный CA и сертификаты доменов |
| `manager.log` | журнал менеджера и движков |
| `instance.lock` | защита от второго запуска |
| `panel.port` | фактический порт панели (если 8080 был занят) |

## Настройка WireGuard

`wg.conf` — обычный клиентский конфиг WireGuard. Его можно положить рядом с
программой (или в каталог данных) либо вставить/загрузить в панели: блок
«Быстрый старт» → «Конфиг WireGuard (wg.conf)». После сохранения менеджер сам
создаёт/обновляет `wireproxy.conf` (порты 25344/25345 и путь `WGConfig`) и
перезапускает канал.

```ini
[Interface]
PrivateKey = <ваш приватный ключ>
Address = 10.66.66.2/32
DNS = 1.1.1.1,1.0.0.1

[Peer]
PublicKey = <публичный ключ сервера>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Важно:

- `Address` — с префиксом `/32` (`/128` для IPv6), так требует wireproxy.
- **MTU**: если туннель «тормозит» на каждом новом соединении, поставьте
  `MTU = 1280` в `[Interface]`. Дефолтные 1420 у многих провайдеров приводят
  к потере крупных пакетов и TCP-ретрансмиссиям.
- AmneziaWG **не** поддерживается — это отдельный протокол.
- Каждому устройству — свой ключ/конфиг: сервер видит один peer, и две
  сессии с одним ключом перебивают друг друга.

Если WireGuard не нужен, оставьте только VLESS: панель сама направит
VPN-домены в живой канал.

## Настройка VLESS/VMess/Trojan/SS (Outline)

В панели (вкладка «Каналы») нажмите «Добавить конфиг» в карточке Xray: имя и
ссылка/JSON. Поддерживаются `vless://…` (Reality, TLS, ws, grpc),
`vmess://…` (base64 JSON), `trojan://…` и `ss://…`. Конфиг сохраняется в
`xray-configs/<slug>.json`; в списке можно выбрать активный, проверить трафик
и удалить его. Активный копируется в `xray-config.json`, xray перезапускается.
Старый одиночный `xray-config.json` импортируется автоматически как «Текущий».
Для Outline используйте статический ключ доступа
`ss://…@host:port/?outline=1#name` — параметр `outline=1` и завершающий `/`
поддерживаются. Динамические ключи `ssconf://…#name` и обычные
`https://…`-ссылки на JSON тоже поддерживаются, если сервер отдаёт валидный
HTTPS-сертификат и `ss://`, JSON с `accessUrl`/`client` или legacy JSON
(`server`, `server_port`, `method`, `password`). Поле `prefix` из legacy JSON
игнорируется: оно нужно Outline для DPI-маскировки salt, а xray использует
обычный salt, который сервер Outline принимает. Если сервер использует
расширенный YAML-конфиг Outline, скопируйте статический `ss://`-ключ.
Несколько WireGuard-конфигов добавляются в карточке WireGuard там же:
«Добавить конфиг» → «Использовать» (активный копируется в `wg.conf`).
Резервная копия включает `xray-config.json`, `xray-configs.json` и
`xray-configs/`.

Подписки: в блоке «Пул конфигов» добавьте URL подписки (обычный текст или
base64) или нажмите **BLACK** / **WHITE (CIDR/SNI)** — менеджер добавит
соответствующие списки из
[igareck/vpn-configs-for-russia](https://github.com/igareck/vpn-configs-for-russia)
и запустит проверку. WHITE-набор пригодится, если провайдер пропускает только
белые списки CIDR/SNI. При загрузке подписок отправляется постоянный HWID
(`x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`) — посмотреть, скопировать
или сменить его можно в «Настройки» → «Приложение». Менеджер:

1. загружает ссылки (только http/https, с проверкой адресов и лимитом 5 МиБ);
2. гоняет каждую через `xray -test`;
3. батчами поднимает тестовый xray (свежие свободные порты) и проверяет
   реальный трафик через каждый конфиг — в список попадают только те, где
   запрос действительно прошёл;
4. сортирует рабочие по задержке и сохраняет в `pool-state.json`;
5. каждые 5 минут перепроверяет рабочие конфиги живым трафиком; перед
   применением выбранный конфиг проверяется ещё раз;
6. при падении активного VLESS-канала переключается на рабочий сам
   (не чаще раза в минуту, цикл — 15 минут).

## Маршрутизация доменов

Страница **«Маршрутизация»** (`/domains/routing`) содержит четыре списка:

- **Напрямую (OpenVPN / LAN)** — всегда мимо VPN, через системные маршруты;
  для этих доменов разрешены частные адреса OpenVPN/локальной сети;
- свои домены через основной VPN-канал;
- только через WireGuard;
- только через VLESS.

Приоритет: исключения (напрямую) → «только VLESS» → «только WireGuard» →
общий VPN-список. Поддомены учитываются автоматически, изменения применяются
сразу. Домены можно добавлять и удалять прямо на странице; в поле домена
можно вставить полную ссылку из браузера.

В «Настройки» → «Основное» есть переключатель **«Частные адреса напрямую»**:
домены вне VPN-списков, которые резолвятся в `10/8`, `172.16/12`,
`192.168/16`, CGNAT или IPv6 ULA, открываются напрямую через маршруты
OpenVPN/LAN. Loopback и link-local при этом остаются запрещены. По умолчанию
выключено, так как это ослабляет SSRF-защиту локального прокси.

## Локальные домены и HTTPS

Блок «Локальные домены» на вкладке «Домены»: домен → локальный порт. Менеджер слушает
`http://127.0.0.1:80` и `https://127.0.0.1:443` (порты меняются в
`settings.json`) и проксирует запросы по заголовку `Host`/SNI на
`localhost:<порт>`. Поддерживаются WebSocket (Vite HMR и т.п.). На macOS
системные порты 80/443 требуют root, поэтому приложение при первом включении
плагина само занимает 8088/8443 и показывает ссылки с нужным портом.

Домены из `local-domains.txt` автоматически попадают в исключения системного
прокси (`ProxyOverride` на Windows, bypass-список на macOS): при включённом
системном прокси браузер ходит к ним напрямую, а не через 8081.

Плагин локальных доменов по умолчанию **выключен**. Его можно включить при
первом запуске (с выбором домена панели) или позже во вкладке
«Настройки» → «Плагины» — порты 80/443 поднимутся, домены вернутся в
исключения системного прокси. При включении панель показывает предупреждение
о сертификатах; при выключении слушатели останавливаются. Архитектура
плагинов и добавление новых протоколов описаны в
[PLUGINS.md](PLUGINS.md) (в панели — «Документация» → «Плагины и протоколы»).

- `*.localhost` браузеры резолвят в `127.0.0.1` сами — правка hosts не нужна.
- Для настоящих имён (например, `app.example.com`) нужна запись `127.0.0.1`
  в hosts. Кнопка «Применить hosts» запускает обновление с UAC (Windows) или
  нативным запросом пароля (macOS) без окон терминала.
- Прокси сам не может заставить браузер резолвить произвольный домен в
  loopback: разрешение имён — это DNS/hosts, а не HTTP-прокси. `*.localhost`
  работают без hosts только потому, что это встроенное поведение браузеров.
- Для «настоящих» имён также можно запустить `wireproxy-control.exe sync-hosts`
  и затем созданный `local-domains-hosts.bat` от администратора (macOS —
  `.command`).
- HTTPS: кнопка «Установить сертификаты» (или `trust-certs`) добавляет CA в
  доверенные через UAC (Windows) или системный диалог пароля (macOS), без
  окна терминала. Firefox: `about:config` →
  `security.enterprise_roots.enabled = true`.
- Существующий `certs/ca.key|ca.crt` переиспользуется, поэтому ранее
  установленное доверие не сбрасывается.

## Панель и системный прокси

Панель: <http://127.0.0.1:8080/> (порт меняется `--panel-port`). Если порт
занят, менеджер сам возьмёт следующий свободный — фактический порт виден в
`manager.log` и в трее. Включение «Системный прокси» прописывает
`127.0.0.1:8081` в настройки прокси системы (реестр + WinINET на Windows,
`networksetup` на macOS). При выходе прокси выключается автоматически, чтобы
не оставить браузер без интернета.

Проверка сайта: «Проверить» открывает домен напрямую, через VPN и через Zapret
(если служба запущена) и предлагает добавить его в список, если VPN помогает.
Вкладка «Сайты» показывает историю за 24 часа с фильтрами «через VPN /
напрямую / нужен VPN / без проверки», проверкой каждого домена и кнопкой
«Проверить все». Фоновая задача раз в 90 секунд проверяет новые домены; при
включённом автодобавлении домен, который не открывается напрямую, но
открывается через VPN, автоматически попадает в VPN-список.

История хранится в SQLite (`wireproxy.db`). В «Настройки» → «Резервная копия»
можно скачать zip с настройками, конфигами, сертификатами и историей или
восстановить его; менеджер перезапустится сам. Бэкап содержит секреты —
храните его в защищённом месте.

PAC-файл: `http://127.0.0.1:<порт панели>/proxy.pac` — `PROXY
127.0.0.1:8081` для доменов списков, остальное `DIRECT`.

Их можно скачивать напрямую (в том числе по ссылке
`https://github.com/devcustrom/vless-pac-proxy/releases/latest/download/<имя>`).
Карточка **«Обновление»** в панели сверяет версию с последним релизом.

Бесшовное обновление: нажмите **«Установить vX»**. Менеджер сам скачает
бинарник, проверит размер/sha256, заменит файл после выхода старого процесса и
запустит новую версию. Страница перезагрузится, системный прокси, настройки и
автозапуск сохранятся. На macOS для `.app` выполняется повторная ad-hoc
подпись; если приложение лежит в `/Applications` и принадлежит другому
пользователю, может потребоваться ручная замена.

Ручной вариант остаётся: «Выход» в трее, замена файла, запуск. Автозапуск
продолжит указывать на тот же путь.

На macOS скачайте `.dmg`, откройте его и перетащите `WireproxyControl` в
`Applications`. Если запустить приложение прямо из DMG, оно само скопируется
в `Applications` (или `~/Applications`, если системная папка недоступна) и
перезапустится оттуда. Первый запуск после скачивания: правый клик по
приложению → «Открыть» — сборка подписана ad-hoc, без нотаризации Apple.
После установки приложение живёт только в menu bar, без иконки в Dock;
панель открывается из меню трея. Если остался зависший процесс старой
версии, завершите его командой `pkill -f WireproxyControl` и запустите
приложение снова. Уже примонтированные старые DMG можно извлечь так:

```bash
pkill -f WireproxyControl 2>/dev/null || true
for v in /Volumes/wireproxy-control*; do
  hdiutil detach -force "$v" 2>/dev/null || true
done
```

Новый DMG извлекает свой том автоматически после установки.

Собрать `.app`, `.zip` и `.dmg` локально на Mac можно командой
`bash scripts/build-macos-app.sh` (нужны Xcode CLT, Node.js и Rust).

## Команды

| Команда | Что делает |
| --- | --- |
| `wireproxy-control` | менеджер + панель + трей (основной режим) |
| `wireproxy-control install` | автозапуск (+ скачивание движков) |
| `wireproxy-control uninstall` | убрать автозапуск (данные остаются) |
| `wireproxy-control stop` | остановить менеджер, выключить системный прокси |
| `wireproxy-control trust-certs` | установить локальный CA (UAC/пароль) |
| `wireproxy-control sync-hosts` | подготовить скрипт синхронизации hosts |
| `wireproxy-control mcp` | MCP-сервер (stdio JSON-RPC) |
| `wireproxy-control version` | версия |

Флаги: `--data-dir <путь>`, `--panel-port <порт>`, `--hidden` (без окна),
`--no-tray` (сервисный режим без иконки).

## MCP для агентов

`wireproxy-control mcp` — stdio JSON-RPC сервер (protocol 2024-11-05) с
инструментами:

- `local_domains_list` — список локальных доменов;
- `local_domains_add` — добавить `домен → порт`;
- `local_domains_remove` — убрать домен;
- `local_domains_probe` — проверить, отвечает ли локальный домен;
- `local_ports` — слушающие локальные порты.

Пример конфигурации MCP-клиента:

```json
{
  "mcpServers": {
    "wireproxy": {
      "command": "C:\\Tools\\wireproxy-control\\wireproxy-control.exe",
      "args": ["mcp"]
    }
  }
}
```

## Интерфейс (Vue 3 + Tailwind + shadcn-стиль)

Исходники панели — в `web/`, это обычный Vite-проект, который можно править:

```
web/
  src/App.vue                 # компоновка и заголовок
  src/components/*.vue        # карточки: каналы, WireGuard, VLESS, пул, домены…
  src/components/ui/*.vue     # примитивы в стиле shadcn: Button, Card, Input…
  src/lib/store.js            # запросы к /api, тосты, опрос статуса
  src/lib/utils.js            # cn() для классов
  src/style.css               # тема shadcn (CSS-переменные)
```

Разработка (менеджер должен быть запущен на 8080):

```bash
cd web
npm install
npm run dev        # http://127.0.0.1:5173, /api проксируется на 8080
```

Сборка и встраивание в бинарник:

```bash
npm --prefix web run build   # создаёт web/dist
cargo build --release        # dist попадает внутрь exe
```

`web/dist` в git не хранится. Если собрать Rust без `npm run build`, бинарник
покажет страницу «UI не собрана». Старый `ui.html` больше не используется —
актуальная панель только в `web/`.

## Сборка из исходников

Нужны Rust (stable), Node.js 20+ и git:

```bash
npm --prefix web install
npm --prefix web run build
cargo build --release
cargo test
```

Бинарник: `target/release/wireproxy-control` (`wireproxy-control.exe` на
Windows). CI (GitHub Actions) собирает фронтенд, затем Windows x64 и macOS
universal, и запускает `cargo fmt --check`, `clippy -D warnings`, тесты.

Движки не входят в бинарник: версии закреплены в `src/engines/downloads.rs`
(wireproxy v1.1.3, Xray v26.11.9) вместе с sha256. Скачивание идёт с GitHub
Releases при первом запуске или через `install`.

## Безопасность и ограничения

- Панель, API, прокси и локальные домены слушают только loopback.
- POST-запросы API требуют заголовок `X-WPC: 1`; Host проверяется по
  allowlist (включая панельные локальные домены).
- При подключении проверяются запрещённые IP-диапазоны (loopback, private,
  link-local, multicast и т.п.) — защита от SSRF/DNS-rebinding.
- Загрузка движков проверяется по sha256; распаковываются только ожидаемые
  файлы, без путей из архива.
- Секреты (`wg.conf`, `xray-config.json`, `pool-state.json`, `settings.json`,
  `certs/`) не попадают в git — см. `.gitignore`.
- Проект не проходил внешний аудит; глубокая проверка Mimosa даёт 0 находок
  при неполном покрытии динамических вызовов. Не считайте его «гарантированно
  безопасным» — используйте на свой риск.

## Старый стек (legacy)

Папка `legacy/` содержит прежнюю реализацию на Node.js/PowerShell/Swift
(`manager.js`, `tray.ps1`, `local-tls.js` и т.д.). Она оставлена для сверки
поведения и не используется бинарником. Форматы файлов совместимы, поэтому
существующая папка данных подхватывается без конвертации.
